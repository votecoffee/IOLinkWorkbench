# IOLinkWorkbench

Read and log one IO-Link sensor on one configured port from a portable Windows x64 desktop application or headless CLI. The application opens offline with a synthetic sensor. Its first hardware adapter targets the ifm AL1350 IoT Core HTTP(S) snapshot API.

## Install

Extract the Windows x64 ZIP into a writable folder. Open **iolink-workbench.exe** for the desktop app or run **iolink-cli.exe** in PowerShell. The package uses the static MSVC C runtime and Windows system libraries. The GUI uses the machine's OpenGL graphics driver. The preview targets Windows 10/11 x64.

Optional XSD validation uses the installed Windows PowerShell and .NET Framework **System.Xml** validator. The application locates Windows PowerShell in the Windows system directory. If that component is unavailable or blocked by local policy, an import that requests XSD validation fails with an error. The validator runs without a visible window or user profiles and has a 20-second limit. Logging and decoding run in Rust.

To build from source, install stable x64 MSVC Rust, the Visual Studio C++ Build Tools, and a Windows SDK. Build from the repository root.

~~~powershell
cargo build --locked --release --target x86_64-pc-windows-msvc
~~~

## Usage

Start with the [operations guide](docs/OPERATIONS.md) for description import, manual setup, CLI recipes and capture interpretation. Contributors can use the [development guide](docs/DEVELOPMENT.md), [repository instructions](AGENTS.md) and [Codex skill](.agents/skills/iolink-workbench/SKILL.md). The opt-in [local HTTP API](docs/LOCAL_API.md) adds bounded live history to CLI/saved-file integration. Optional [MQTT publishing](docs/MQTT.md) provides a separate latest-state feed. The opt-in [Windows shared-memory snapshot](docs/SHARED_MEMORY.md) supports local readers. C FFI remains a [planned interface](docs/INTERFACES.md). The development guide explains installing the skill for discovery.

In the GUI, use **Setup** to load, edit, and save a named TOML profile. The profile editor accepts the same TOML as the CLI. Choose **Inspect IODD** to list the variants and input layouts, select the matching entries, then use **Apply IODD layout**. The effective field list distinguishes IODD fields, overrides, and manual fields. **Edit mapping** opens a typed field editor; applying an imported field creates a host override. **Add manual field** opens a new field draft. Apply edits before connecting or saving.

Use **Host connection settings** in Setup to choose the simulator or AL1350 adapter, host endpoint, port, expected installed firmware, expected numeric mode, confirmed cycle unit, polling/timeout/stale/reconnect intervals, and simulator freshness. **Apply host settings** validates a candidate and updates the applied profile locally; **Save / replace profile** writes it to disk. **Discard host settings** restores the last applied connection. The form and TOML editor retain separate drafts, and pending edits must be applied or discarded before starting monitor/capture, parameter reads, saving/loading, or applying another IODD mapping. Failed validation preserves both the applied profile and the draft for correction. Use the field editor for cyclic mappings and the advanced TOML editor for input byte width and other profile settings.

Use **Expected device identity** in Setup to pin Vendor ID, Device ID, Product ID, product name or serial. Check a field to enable its pin; uncheck it to ignore that field. Numeric pins accept decimal or **0x** hexadecimal and require a value when enabled. Text pins are literal, including spaces and empty strings. **Apply identity pins** updates the local profile; Save persists it. The selected IODD variant is shown separately, with a review note if its Product ID differs from the expected pin. These controls configure expectations; they do not read or verify a connected device.

Use **Monitor & CSV** to inspect the configured port or start a capture in a new directory. Expand **CSV values and order** to choose values, switch to **Raw only**, or move selected value columns up/down. **All mapped values** restores mapping order. Save the profile in Setup to retain these choices. **Stop and flush** drains the writer. Use **Offline decode** to paste a hexadecimal input and view the same raw and typed fields without a connection.

**IODD scope.** The importer accepts UTF-8 or BOM-tagged UTF-16 IODD 1.1 XML and ZIP bundles. ZIP imports select a unique main IODD by filename or accept an exact member with **--entry**. Use **--variant** when the IODD lists several product IDs and **--layout** for multiple or conditional input layouts. For conditional physical captures, set **confirm_iodd_condition = true** after verifying the active condition on the sensor. The importer supports scalar signed and unsigned integers, Boolean and Float32, including those fields in an input record or top-level array. Array fields receive stable one-based element suffixes such as **Temperature [2]** and share the array's process-input display metadata. It resolves local datatype references, selected-language names, process-input display scaling, and unit codes. Unit code 1997 explicitly specifies no unit. Unsupported fields, unknown unit codes, and conditions appear for review. Duplicate variant, datatype, language, or text IDs and overlapping supported input fields are rejected. Profile snippets, nested complex layouts, and additional IODD Checker semantic/stamp checks are roadmap items.

**Languages and units.** Add **--language TAG** to **iodd** or **import** to select an embedded **Language** or a companion **ExternalTextDocument**. Without a tag, the importer uses **PrimaryLanguage**. For XML, a requested companion is the adjacent **MAIN-STEM-TAG.xml**. For ZIPs it is the matching **MAIN-STEM-TAG.xml** in the selected main entry's folder; no files are extracted. ZIP catalogs list language tags discovered from companion filenames, and the selected file's declared **xml:lang** must match. **--language-file PATH** selects an explicit language XML and requires a tag. Tags match case-insensitively. Missing translated IDs use the primary text and are listed in **iodd.localization.fallback_text_ids**. Conflicting embedded/external definitions, duplicate IDs, unknown translation IDs, and differing declared release dates cause an error. Standard parameter and event text uses the supplied definitions and their selected-language companion when available; supported Direct Parameter Page 2 **TextRedefine** labels are applied after standard localization.

Add **--unit-definitions PATH** to load abbreviations from a local **IODD-StandardUnitDefinitions1.1.xml**. Supplied codes take precedence, other common codes use the built-in table, and unresolved codes remain visible for review. Abbreviations affect display/CSV units and preserve the mapping's gradient and offset. The full official V1.1.9 table contains 688 entries. The included **synthetic-unit-definitions.xml** is an original minimal fixture. Obtain official files from the [IO-Link Community download area](https://io-link.com/downloads) and keep them in ignored **.local/**.

GUI Setup has the same optional language, explicit language XML, and unit XML inputs. Inspection displays the selected language, available tags, fallback count, and unit source. Saved profiles retain the resolved labels/units, language choices, fallback IDs, and supplied resource filenames/version. Reimporting in another language changes field names and CSV headers; review retained manual fields, overrides, and logging selections before use. Existing profiles retain their saved names and units. XML companion/unit resources receive parser checks; the optional XSD receipt continues to cover only the main XML.

**Standard-definition languages.** With **--standard-definitions FILE.xml**, the importer follows the selected device-text language, including its primary language when **--language** is omitted. It uses an embedded standard language or the adjacent **FILE-STEM-TAG.xml**, such as **IODD-StandardDefinitions1.1-de.xml**. Even when the device IODD comes from a ZIP, standard definitions and their companions are explicit local XML resources; they are not searched for inside the device archive. Add **--standard-language-file PATH** to select a different standard translation filename. This override requires both **--language TAG** and **--standard-definitions**. GUI Setup has the same optional standard-language path. Automatic local companions use the existing bounded XML reader and reject links/reparse points; imports never fetch a language file from the network.

Resolved parameter names, record-member names, choice labels, and standard event names/descriptions use that standard text table. IDs, indexes, access restrictions, widths, defaults, and raw decoding remain unchanged. If the requested standard language is absent, standard definitions use their primary language and add a review note. A partial translation keeps primary-text fallbacks. Unknown or duplicate text IDs, mismatched language tags, conflicting embedded/companion definitions, and differing declared release dates or versions are rejected. Revision comparisons apply when both documents supply the corresponding metadata. An explicit missing or invalid file fails the import and preserves an existing output profile.

The saved **iodd.localization.standard_definitions** table records definition source/version, requested/selected/primary language, translation source, fallback IDs, and review notes. Setup shows the selected standard language and fallback count. Profiles carrying this optional table require Workbench **0.18.0** or newer; older profiles without it remain readable. The original partial **synthetic-standard-definitions-de.xml** fixture demonstrates translated Product ID and event labels while retaining the simulator's raw responses. These synthetic fixtures are parser examples, not complete official-XSD test documents.

The offline audit of the local released 2025 [IO-Link Community resources](https://io-link.com/downloads) accepted standard translations for **de, es, fr, it, ja, pt, ru, zh** with no text fallbacks. All 22 main example IODDs imported, plus German/Chinese selections for both internal- and external-language examples. The supplied Korean standard-language file declares **2022-03-15**, while the base definitions declare **2021-01-21**; this application rejects that mismatch under its date-matching policy. This is a resource compatibility limitation, separate from physical device acceptance. Vendor files are not included in the portable package.

**Declared cycles and the 1 ms target (0.23.0+).** Wired **CommNetworkProfile/TransportLayers/PhysicalLayer** declarations import into **iodd.communication**: IO-Link revision, optional V1.0 compatibility, COM1/COM2/COM3, minimum cycle in microseconds, SIO support, and the M-sequence capability octet. This uses the [IODD V1.1.5 section 7.6](https://io-link.com/downloads) representation directly; **minCycleTime="2300"** means **2300 µs**, not an encoded IO-Link time byte. The parser checks the specified ranges/steps: 0–6300 by 100, 6400–31600 by 400, and 32000–132800 by 1600. Duplicate wired elements, invalid declared values and unsupported wired revision/rate values reject import. Missing or unrecognized transport representations remain unavailable; wireless timing is not interpreted as wired timing. Test/connection child declarations do not cause device commands or configuration changes.

Run **timing PROFILE [--target-us N]** to compare the saved IODD minimum with the profile's requested host poll interval, without opening its endpoint. The target defaults to **1000 µs**. GUI Setup shows the same profile-only comparison; Monitor adds the last accepted connection's port-cycle report when its microsecond unit is known. Results report **shorter**, **equal**, **longer** or **unknown** relationships. Zero is retained as a declaration but treated as unavailable in comparisons. For an IO-Link minimum of zero, the master determines M-sequence timing; Workbench does not calculate that negotiated result. A target at or above the declared minimum does not establish a supported source-update rate or gateway throughput.

A reported port cycle below the IODD minimum raises a review note for identity, cycle units and active configuration. Faster host polls can repeat a source update. COM is a line-rate declaration; sensor conversion, negotiated port cycles, gateway updates and host receive spacing still need separate measurements. Snapshot gateways retain unknown source-update loss, and simulator timing remains synthetic. No poll interval, port mode, device parameter or output is changed by these comparisons.

Captures with declarations copy them into **capture.toml/iodd_communication**, separately from the saved profile and measured distributions. **review-capture** exposes a **cycle_context** comparison for the 1 ms target using the original profile and last accepted connection status; GUI saved-capture review displays it alongside the existing measurements. Verification rejects conflicting report/profile declarations and differing requested host poll intervals. Re-decoding retains the original acquisition metadata independently of the new value mapping. Earlier reports without a requested interval keep that comparison unknown. Profiles/captures/snapshots containing the new declaration table require **0.23.0 or newer**; older files remain readable without inferring missing declarations or reopening the original IODD.

The original abbreviated **sensor-communication.xml** fixture declares COM2 / 2300 µs, while the independent simulator still reports its synthetic 1000 µs cycle. This deliberately exercises the review note and does not model a physical device. The offline audit retained the declared COM2 / 2300 µs metadata from all **22** supplied official example IODDs with matching stamps. No bench measurements or physical acceptance are implied.

**IODD checksum stamps (0.22.0+).** File/ZIP imports check the selected main XML and any selected external language document against their **Stamp/@crc**, following [IODD V1.1.5 section 7.3.4](https://io-link.com/downloads). **check-stamp XML_OR_ZIP [--entry MEMBER] [--language TAG] [--language-file FILE]** prints a read-only receipt and exits 0 only when every inspected stamp matches. Missing, mismatched, malformed, or unbound stamps produce exit 1 with their report; malformed XML/input errors retain the usual error output. No gateway is opened, and no stamp is written or repaired.

CRC-32/ISO-HDLC covers the original binary stream with only the actual crc attribute value omitted. BOMs, physical line endings, spaces, comments, and original UTF-8 or BOM-marked UTF-16 bytes are retained in the calculation. The selected language document additionally appends the verified main CRC as decimal ASCII without leading zeros. XML attribute ranges locate the real Stamp; comment/text decoys do not substitute for it. File receipts show **matched**, **missing**, **mismatch**, **malformed**, or **unbound**, source filename/member, SHA256, byte count, encoding, claimed/calculated CRC, language binding, and the declared Checker name/version. A language stamp is **unbound** when no matching main CRC is available.

Present mismatches and malformed stamps reject **iodd/import** before a new mapping is accepted or a saved profile is replaced. Missing stamps remain visible by default so original abbreviated fixtures and unstamped offline drafts can still be inspected. Add **--require-stamp**, or select **Require matching main and selected-language checksums** in GUI Setup before inspection, to require matching stamps for every document actually inspected. This option does not require an unavailable translation to exist; normal language fallback/review still applies. Only the selected main XML and external language are covered. Other ZIP entries, images, supplied standard definitions/units, and unused translations are not checksum-verified by this feature. XSD validation remains an independent optional check.

Successful file imports save **iodd.stamp_validation** receipts. Receipt consistency is validated on profile/snapshot load without reopening recorded source paths; any saved XSD and stamp receipts must identify the same main XML hash. Existing profiles/snapshots without receipts remain readable and report checksum verification as unavailable. Profiles newly imported in 0.22.0 and snapshots containing their new receipt require **0.22.0 or newer**. Reopening preserves original snapshot bytes. An editable receipt is not authenticated acquisition evidence. A CRC match does not authenticate the vendor or declared Checker identity, rerun the official Checker, establish profile-snippet conformance, or prove connected identity/physical operation. The checker name/version are unverified file metadata.

The bundled **sensor-checksum.xml** and **sensor-checksum-de.xml** are original synthetic parser fixtures with independently calculated CRC test values. Their Checker metadata explicitly identifies a Workbench test fixture; they are not official Checker output or complete official-XSD examples. The offline audit matched all **22** supplied official example main documents and both external-language documents, without modifying vendor files or executing the vendor Checker.

**Optional XSD check.** Obtain the matching IODD 1.1 schema directory from the [IO-Link Community specification package](https://io-link.com/downloads), including its local includes and **xml.xsd**, and keep it under ignored **.local/**. Run **check-iodd XML_OR_ZIP --xsd ROOT_XSD [--entry MEMBER]** for a full machine-readable report. Add **--xsd ROOT_XSD** to **iodd** or **import** to require a validation pass before inspecting or saving a profile. In GUI Setup, enter the optional root XSD before **Inspect IODD**. Inspection runs in a background worker, and schema failures leave the applied profile unchanged.

~~~powershell
.\iolink-cli.exe check-iodd .\.local\vendor-device.zip --xsd .\.local\schemas\IODD1.1.xsd
.\iolink-cli.exe import .\.local\vendor-device.zip .\.local\checked.toml --variant YOUR-PRODUCT-ID --xsd .\.local\schemas\IODD1.1.xsd
~~~

The checker uses [System.Xml XSD 1.0 validation](https://learn.microsoft.com/en-us/dotnet/standard/data/xml/xml-schema-xsd-validation-with-xmlschemaset), including schema identity constraints. Reports include line/column diagnostics and SHA256 hashes of the selected XML's exact bytes and the schema files used. Successful imports save this receipt under **iodd.schema_validation**. The GUI and **validate PROFILE** distinguish a saved main-XML validation pass from parser checks alone. Existing profiles load with validation unperformed unless they contain a receipt. The receipt records the original XML/schema check; profile edits, standard-definition XML, IODD Checker semantic rules, checksum stamps, connected identity, and physical operation have separate checks. A supplied schema's authenticity remains a user choice.

Schema includes/imports are explicitly loaded from within the selected local schema directory. HTTP, UNC/network-drive roots, escaping paths, and child reparse points are rejected. DTDs are prohibited. Document-supplied schema hints and inline schemas are ignored. Limits are 8 MiB per XML/schema file, 64 schema files, 32 MiB of schemas, and 100 diagnostics. Validation warnings also prevent an import pass. The helper is attached to an application-owned Windows job and is terminated if the application exits. Official schemas are supplied locally and are excluded from the portable ZIP. The bundled synthetic IODDs are parser/decoder fixtures with abbreviated headers; use vendor IODDs or official examples for validation against the complete official schema.

**Manual mapping.** Set **input_bytes** to the exact input width. Each **[[fields]]** table describes a value with a name, bit offset, width, kind, byte order, scale, offset, and unit. Bit zero is the least significant bit of the last payload byte for big endian, or the first payload byte for little endian. The decoded value is **raw × scale + offset**. Optional **decimals** controls the decimal places in the typed display and CSV. A field with the same name as an imported field replaces its mapping. Set **logging.fields** to an ordered list of effective names or leave it empty to log all mapped fields. Set **logging.raw_only = true** with an empty **logging.fields** list for metadata/raw-only CSV; the mapping remains available for typed previews and offline re-decoding. The raw payload is always included in CSV. Profiles reject selected name/unit combinations that would generate duplicate CSV column labels.

**Device diagnostics.** IODD imports save event codes, declared types, localized names, and descriptions. Referenced **StdEventRef** definitions use the optional **--standard-definitions** file; unresolved codes remain listed for review. Use **events PROFILE** to browse the saved catalog. Older profiles can be reimported to add event metadata.

In **Monitor & CSV**, expand **Device diagnostics (explicit ISDU reads)** and choose **Read device diagnostics**, or run **read-diagnostics PROFILE**. This explicitly reads standard Device Status **36:0** and Detailed Device Status **37:0** on independent acyclic clients with the usual identity checks. Each read reports its raw bytes, host UTC completion time, monotonic query duration, and available connection identity. A failed query retains the other query's successful result. Read failures, malformed payload lengths, or differing observed identity fields produce a nonzero CLI exit. The two reads are separate snapshots; they do not establish an atomic device state or a complete event history. Source event loss stays unknown, and cyclic logging does not initiate these reads.

The decoder follows the [IO-Link Interface specification](https://io-link.com/fileadmin/user_upload/Downloads/Package_2024/IOL-Interface-Spec_10002_V114_Jun24.pdf): each Detailed Device Status slot contains one qualifier octet followed by a big-endian two-byte event code. It accepts 1–64 complete slots, counts all-zero empty slots, and preserves raw bytes and slot positions. Qualifier fields show instance, source, type, and mode. Saved device IODD names apply only to device-application events. Reserved fields, unknown codes, unexpected pending-event shapes, and type mismatches receive review notes. An empty slot list does not establish overall device health.

Use **decode-diagnostics PROFILE HEX [--device-status HEX]** or **Offline device diagnostics** in the GUI for a recorded response through the same decoder. The synthetic sensor returns **02** at **36:0** and **E48DFE000000** at **37:0**, containing one synthetic warning and one empty slot. Gateway **device_status**, **port_event**, and **device_event** fields remain raw connection-time snapshots. CSV **diagnostic_code** is the transport response code. Those gateway fields are separate namespaces from these standard ISDU values. Device support and the timing impact of diagnostic queries remain physical bench checks.

**IODD parameters.** Importing an IODD also saves its explicit **Variable** definitions in the profile. The catalog shows parameter IDs, names, indexes, declared access rights, defaults, supported single-value labels, and ranges. In **Monitor & CSV**, expand **IODD parameters**, select an entry and subindex, and choose **Read named parameter**. The CLI provides **parameters PROFILE** for offline browsing and **read-parameter PROFILE ID [--subindex N]** for one explicit ISDU read. Subindex zero selects the whole variable. Older profiles can be reimported to add this metadata.

Named reads use the independent acyclic client and report the raw bytes, supported raw scalar or text value, host read time, and total query duration. Integer, Boolean, Float32, UTF-8, and US-ASCII decoding are supported. Numeric **VariableRef** and **RecordItemRef** menu entries supply gradient, offset, common unit codes, and **Dec.0** through **Dec.12** formatting. Read results retain each supported menu display separately alongside the raw value. Multiple menu displays, missing or unknown units, unsupported formats, and complex types appear for review. Unsupported parameter values remain available as raw hexadecimal. A decoding error retains the returned bytes for review. Write-only named entries are rejected before transport access. IODD defaults and ranges describe the device's declared settings.

**Parameter number formats.** Acyclic menu displays support plain **Dec**, **Dec.0** through **Dec.12**, integer **Hex**, integer **Bin**, and Boolean **Dec**. Format rules follow Table 2 of the released IODD V1.1.5 specification available from the [IO-Link Community](https://io-link.com/downloads). Each display keeps its menu/reference ID. The GUI shows the format with its declared scaling and unit, and live/offline decoding uses the same formatter. Raw bytes and raw scalar values remain available alongside every formatted display.

Hexadecimal uses uppercase digits and an **h** postfix, such as **01F4h**. Binary uses four-bit groups and a **b** postfix, such as **0000 0001 1111 0100b**. Integer views pad to 8, 16, 32, or 64 bits; negative signed values use two's complement with sign extension to that display width. Packed record/array members and standalone member responses share these rules. Unscaled 64-bit values remain exact without floating-point conversion. Boolean **Dec** displays **0/1** while retaining **false/true** as the raw scalar value.

## AL1350 bench setup

The adapter follows ifm's AL1350 IoT Core contract for the 3.1.x firmware documentation. It uses a Rust HTTP client and the Windows Schannel TLS backend and requires no ifm SDK, driver, moneo runtime, or application license key for the implemented requests. The AL1350 model and actual firmware are read at connection. This adapter has passed a loopback contract fixture. Hardware and individual firmware revisions await bench qualification. [ifm product data](https://www.ifm.com/gb/en/product/AL1350?tab=documents) · [ifm AL1350 operating instructions, 80284128/03](https://www.quicktimeonline.com/assets/images/pdf/IFM%20Electronic/operating-instruction-AL1350.pdf)

1. Copy [the AL1350 template](samples/ifm-al1350.toml) to **.local/**. Enter the Ethernet IoT endpoint, an already configured IO-Link port, the sensor's input width, and its mapping or imported IODD. Set an exact **ifm_firmware** pin once you know the version.
2. Confirm the port mode in the existing gateway setup. If the endpoint reports a numeric mode, set **ifm_mode** to the confirmed IO-Link mode code. The application checks the mode and reads the connected device's numeric IDs before sampling. Pin the expected IDs, and optionally product name or serial, to reject mismatches.
3. If the installation uses HTTPS, Windows must trust the gateway certificate. For enabled IoT Core authentication, set **IOLINK_IFM_PASSWORD** in the process environment and use an HTTPS origin. The adapter sends the documented administrator authentication object over TLS.
4. Use **status** before capture. If the profile pins an IODD Product ID, **status --verify-product-id** or **Verify Product ID** in the GUI reads ISDU index 19:0 and compares it explicitly. During capture, the gateway's cyclic snapshot endpoints supply Vendor ID, Device ID, product name, and serial where present. Product ID verification and other explicit ISDU reads use a separate client and worker. The gateway or port can still have shared service time.
5. Confirm the sensor's byte order and values against a known observation before relying on typed data. The gateway's reported cycle is preserved raw. Set **ifm_cycle_unit** to **microseconds** or **milliseconds** after confirming the unit for the installed firmware. The cited manual gives conflicting units in its setup and API sections.

The app sends only documented data reads and explicitly requested ISDU reads. Port configuration, device commands, ISDU writes, and process outputs are outside this build.

## Capture files and timing

**Compare saved captures.** Use **compare-captures LEFT RIGHT** or GUI **Compare two saved captures offline**. Both folders are fully verified before results appear. Timing and loss domains remain separate, missing values stay unavailable, and arithmetic differences require matching recorded settings; count differences also require identical recorded duration. This is descriptive saved-record evidence, with no clock alignment or performance/physical acceptance verdict. See the [comparison policy](docs/CAPTURE_REVIEW.md#compare-two-captures).

**Saved timing validation.** All capture verification/review/export paths now reject inconsistent recorded spacing aggregates, contradictory available observation counts, and host intervals beyond the acquisition window. Independent gateway timestamps keep their own clock domain; absent legacy measurements stay unavailable. See [timing consistency](docs/CAPTURE_REVIEW.md#recorded-timing-consistency).

**Saved interface diagnostics.** Run **review-interfaces DIRECTORY** or use **Verify capture** in the GUI to verify every CSV part and inspect saved HTTP/MQTT/shared-memory counters, acquisition/logger timing, availability, metadata hashes and categorized findings. This works for raw-only captures. Intentional coalescing, retention, uncertain delivery and interface loss stay separate from source gaps and CSV overruns. Missing metrics remain unrecorded, and no endpoint or mapping is opened. **Review field** includes the same diagnostics when present. See the [offline review guide](docs/CAPTURE_REVIEW.md).

**Saved logging controls and offline plan.** Use **set-logging INPUT OUTPUT** with **--mode every-update|on-change**, **--queue-capacity N**, **--rotate-rows N**, **--rotate-seconds N**, and one of **--raw-only**, **--all-fields**, or repeated ordered **--field NAME** options. At least one edit is required. Unspecified settings remain intact; publication refuses an existing destination. Queue capacity is 1–1,000,000; edited rotation values must fit TOML's signed 64-bit integer range. Zero disables a rotation limit. **logging PROFILE** prints configured row semantics, settings, selected field mappings/origins and exact CSV columns without opening a gateway. The GUI exposes the summary under **Configured capture plan (offline)** while idle. This plan verifies no runtime freshness or rate. Rotation checks either threshold before the next row; elapsed time comes from receive timestamps relative to the first row in each part, so silence produces no empty timed parts. See the [operations guide](docs/OPERATIONS.md#choose-logging-and-inspect-its-plan) for examples.

Each run creates a new directory with **profile.toml**, **capture.toml**, and UTF-8 **capture-NNNN.csv** files. Rotation uses the configured row or elapsed-time limit. Each CSV has the UTC origin, monotonic host receive elapsed time, selected sample index, connection generation, row kind, validity, staleness and source metadata where exposed, diagnostic code, raw bytes, and selected typed values. Typed cells are blank for invalid or known-stale rows. A queue overrun drops the newest selected row and leaves a gap in saved sample indexes. Ctrl+C requests a clean drain and returns exit code 130 after the report is saved.

The report accounts for selected rows as **csv_rows_flushed + csv_rows_unconfirmed + counts.logger_overruns**. Unconfirmed rows were accepted by the queue but have no confirmed successful flush. A writer error stops the capture and retains its report and completed CSV parts. Staleness uses both the gateway-reported age and the time since the host last observed an advancing source counter or timestamp. A frozen source therefore becomes stale even when the gateway continues reporting zero age.

**Logger pressure and timing.** New captures include **logger_metrics** in **capture.toml**. The GUI shows **Recorded logger pressure and timing** after capture and during saved signal review. CLI capture output and **review-capture** expose the same saved measurements. These host operation durations are separate from IO-Link cycle, gateway update timestamps, and host poll/receive spacing.

The report records configured **queue_capacity**, **queue_high_water_observed**, **rows_dequeued**, and **final_drain_us**. Queue high water is a lower bound observed after accepted pushes and at full-queue failures; a concurrent consumer can remove rows before a depth observation. It excludes the row currently being processed. **final_drain_us** measures the stop request and writer join after acquisition ends, including any remaining queue drain, final flush and file sync. The existing **elapsed_us** continues to describe the acquisition window and excludes this final drain. Writer errors and unconfirmed-row counts still determine whether the data was completely flushed.

Each measured **queue_wait**, **row_service**, **flush**, and **sync** group reports attempt count, p50, p95, p99, longest, and approximate mean in microseconds using a monotonic host clock. Queue wait runs from the enqueue attempt to dequeue and excludes row service. Row service runs from dequeue through that row's CSV write, including decoding, buffer work, rotation, measurement bookkeeping, and any explicitly simulated writer delay. It ends after buffering; it does not measure durability per row. **flush** measures explicit CSV flush calls, while **sync** measures file **sync_all** calls. Periodic/final flushes can fall outside row service; rotation flush and sync fall inside it. These durations overlap and must not be added together. Failed attempts contribute timing when the call returns; **writer_error** retains the failure. Missing groups mean no measured operations, not zero latency.

New logger measurements require Workbench **0.17.0** or newer to display and check. Older captures remain readable and show logger measurements as unavailable. Verification checks queue capacity, dequeued-row accounting, attempt counts, finite means, and ordered quantiles where these metrics exist. Synthetic delay/backpressure, empty writers, rotation failures, and malformed report checks qualify this host accounting. Actual disk behavior and the 1 ms target remain physical bench measurements.

If a reconnect is rejected, **last_status** retains the last accepted device and its freshness contract. **rejected_status** records the rejected candidate. The report's **format_version = 1** identifies the saved capture format.

Use **verify-capture DIRECTORY** or **Verify capture** in **Review saved capture** under the GUI's **Offline decode** tab to inspect a finalized run using its saved profile. Verification checks the complete numbered part set, headers, final records, UTC origin, sample and generation order, freshness metadata, raw-to-typed decoding, and CSV row accounting. It accepts the earlier capture reports that omit the format version or unconfirmed-row count. A verification error identifies the affected file and data row where available.

Pass **--joined-csv NEW_FILE** to combine the checked parts into one UTF-8 CSV with LF record endings and one header. The new file is published after all checks pass. Existing destination files cause an error. Missing selected sample indexes describe rows absent from CSV, and recorded source-loss fields retain the original report's meaning. The verification summary includes **capture_had_error** when the original acquisition reported a terminal or writer error. Successful verification establishes consistency between the saved files and report.

**CSV value selection.** In **Monitor & CSV → CSV values and order**, each checkbox selects a mapped value for CSV, with its unit and IODD/manual/override origin shown. Hover for its bit layout and scaling. Use **Up/Down** to choose value column order. **All mapped values** restores the mapping's order. Clearing the final value switches to **Raw only**. Selection controls are disabled during a session or pending Setup edits. A failed selection, including colliding CSV labels, retains the previous settings.

Use repeated **capture --field NAME** options to override the saved value selection in that exact order. Names are literal, including spaces, commas, Unicode, and brackets; no comma splitting is performed. **--raw-only** writes only the 12 metadata/raw columns, and **--all-fields** selects all mapped values. The three forms are mutually exclusive. Unknown or duplicate names fail before opening the transport or creating the capture folder. The input profile file remains unchanged; the capture's saved profile records the effective selection. Without these flags, capture uses the saved profile's selection.

Raw-only mode keeps the full mapping and the usual configured input-width, identity, layout, validity, and freshness checks. It supports both logging modes, rotation, capture verification, CSV joining, and subsequent re-decode export with a typed mapping. Signal review needs at least one logged typed column, so it reports that no typed fields are available for a raw-only capture. On-change selection continues to compare the whole raw input, validity, staleness, and transport diagnostic code. CSV value selection does not filter acquisition updates or reduce those comparisons. Existing profiles retain their previous behavior. The optional **logging.raw_only** key requires Workbench 0.13.0 or newer; false is omitted when saving ordinary profiles.

**Offline signal review.** Run **review-capture DIRECTORY [--field NAME] [--buckets N]** to verify every CSV row and review one logged field in the same streaming pass. The field name must exactly match the saved logging selection; omission selects its first field. In the GUI's **Review saved capture** section, choose **Review field**, then select another saved field and review again if needed. Review uses the saved capture profile and does not open its gateway endpoint or use the current Setup profile. It retains the verification summary, source-loss meaning, generation count, recorded logger overruns, and any original capture-error flag.

Statistics use the saved typed CSV cells, including their scaling and decimal formatting. Blank cells for invalid data, unknown validity, or known staleness are counted separately from non-finite numeric cells; both groups are excluded from numeric statistics. Boolean false/true becomes 0/1. Minimum, maximum, mean, and plotted values use approximate **f64** arithmetic; integers wider than 53 significant bits may lose numeric precision. The first and last nonblank cell texts remain exact, including non-finite representations. The source CSV and raw bytes remain unchanged. These describe saved rows: change-only selection, invalid/stale periods, and missing rows prevent interpreting the mean as a time-weighted or complete source-population mean.

The preview allocates **1–4096** time bins across the recorded host elapsed interval, independently of capture length. Each bin retains finite minimum/maximum and the last finite value, preserving observed extrema rather than selecting occasional rows. Empty bins remain empty. The GUI draws independent range marks and a last-value dot, with amber shading for bins containing blank/non-finite cells or multiple generations. No lines join bins. Bins may group multiple events or generations; use the CSV for exact ordering. All capture parts and fields must pass verification before a review result is returned.

The GUI also shows the acquisition report's recorded port cycle, requested host interval, and separate host poll, host receive, observed new-update, and gateway timestamp spacing summaries. These are retained measurements from the original acquisition, not timing inferred from the reduced CSV row set. Missing legacy measurements remain unavailable. The configured transport, recorded route, and simulation settings remain visible; offline review does not establish physical hardware acceptance.

**Re-decode saved payloads.** Run **redecode-capture DIRECTORY MAPPING_PROFILE NEW_EXPORT_DIRECTORY** to verify the original capture and decode its raw inputs with another saved profile. In **Offline decode → Review saved capture → Re-decode with applied Setup mapping**, use the current applied Setup profile and choose **Export re-decoded CSV**. Pending Setup edits must be applied first. This action does not connect to either profile's endpoint, query a device, change configuration, or perform device identity verification. It accepts the mapping as a new interpretation of existing bytes. The bundled **samples/redecode.toml** demonstrates a revised scale and offset for the synthetic sensor.

The mapping must have the same input width as the source capture and at least one selected typed field. It uses the ordinary effective IODD/manual fields, overrides, byte order, signedness, scale, offset, decimals, units, and **logging.fields** order. Every original field and CSV part must still pass verification. Invalid data, unknown validity, and known staleness retain blank typed cells. The first 12 metadata cells, including the raw payload, sample index, monotonic receive time, generation, validity, staleness, source metadata, and transport diagnostic code, are copied as strings. CSV quoting is regenerated with UTF-8, comma separators, and LF record endings.

Choose a new export directory outside the source capture, with an existing writable parent. The application flushes and syncs the completed files before publishing the directory on Windows without replacement. Source validation, mapping/width failures, write errors, and destination collisions leave the final export unpublished. The source files are preserved. A capture with a recorded terminal or writer error can be exported only when its saved rows pass verification; the original error flag and source-loss meaning remain in the receipt. Unconfirmed CSV rows prevent export.

Each bundle contains **data.csv**, the effective serialized **mapping-profile.toml**, exact copies **source-profile.toml** and **source-capture.toml**, and **receipt.toml**. The receipt identifies the operation as **offline_redecode** and records source verification, row counts, selected fields, application version, and SHA256 hashes/byte counts for the source profile, report, all CSV parts, and four exported data/profile/report files. Source part hashes are computed from the same stream that was verified. The receipt is excluded from its own hash list. Original CSV parts are referenced by hash rather than copied again. These hashes identify the bytes read; they do not authenticate the original source or establish a calibration. The bundle uses distinct filenames and has no new **capture.toml** acquisition report. The retained source report still describes the original acquisition profile and timing.

**Verify re-decoded bundles.** Run **verify-export EXPORT_DIRECTORY** to inspect a copied or original bundle. It checks the four local file hashes and byte counts, saved profiles, receipt kind/version, exact file inventories, mapping definitions and field order, CSV header, every raw-to-typed value, receive/sample/generation order, validity/staleness, and row accounting. Blank typed cells and original acquisition error/source-loss flags retain their meaning. Metadata files have a 16 MiB limit; data CSV is streamed. The verifier reads only the fixed bundle filenames and rejects child symlinks/reparse points. Recorded source/output directory paths are informational and are never followed automatically.

Add **--source CAPTURE_DIRECTORY** to explicitly reverify an available original capture, including all original typed fields and CSV parts. It compares the exact source profile, report, and CSV hashes against the receipt and compares every copied metadata/raw cell and revised value against that verified source stream. A relocated byte-identical source is accepted. A missing or mismatched supplied source causes failure. This option does not open either profile's gateway endpoint.

The report distinguishes **original_source_reverified = false** for local bundle consistency from **true** after the optional complete original-source comparison, and counts original CSV hashes separately from local hashes. Hashes describe consistency with the stored receipt; the receipt has no signature. Receipt authorship, device identity, calibration, and physical acceptance remain unverified. A consistent edited bundle/receipt can pass local checks while failing comparison to its byte-pinned original. In the GUI, expand **Verify re-decoded bundle**, enter the bundle folder, and optionally select **Also reverify the original Capture folder above**. The result labels the scope and retains any saved acquisition error, including an empty capture with a terminal error.

- **Every update** writes each observed, verifiably new update when the adapter provides source freshness. Equal payloads with new counters still log. Counter gaps are counted within a connection generation. The first update after reconnect starts a new generation and loss during the disconnect is unknown.
- **On change** compares the whole raw payload, validity, stale flag, and diagnostic code within a generation. It emits the first eligible row in each generation. A full queue leaves the previous queued value as the comparison point, so the next eligible observation can retry a dropped change.
- **AL1350 snapshots** are always labeled **host_poll**. The response's IoT Core status distinguishes success and documented invalid-data errors. The snapshot service exposes no source timestamp or update counter. Input age, source-update loss, and gateway update cadence stay unknown on this path. Repeated successful reads do not establish freshness.
- **Timing** reports p50, p95, p99, longest gap, and mean rate for host poll starts and host receive completions. It separately reports observed new-update receive spacing and gateway timestamp intervals where available. The master-reported IO-Link port cycle is its own field. Host timing includes scheduling and network/API effects. **1 ms** is a target for the eventual sensor and gateway qualification.
