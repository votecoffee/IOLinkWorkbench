# Live observation age and retained input

Monitor & CSV displays the last observation delivered to the GUI. It does not issue an extra gateway read when painting a value. **Validity at receipt** and **Gateway input age at receipt** retain the adapter's recorded meaning. The host's **last received** age advances using the same process's monotonic clock. Where counter/timestamp metadata verifies source updates, **Time since last observed update** also advances from the host instant at which that update was observed. That host timer is not an absolute sensor timestamp or proof of the latest update currently available inside a gateway.

Typed values appear only while the session is running, the last observed connection is connected, receipt validity is valid, receipt staleness is not true, and the held observation/update is within the GUI's display-age budget. A stopped session, disconnection, invalid/unknown validity, known receipt staleness, or an exceeded display-age budget hides typed values and presents the reason. Raw input remains available for inspection. Use Offline decode or saved-capture review for typed historical values. A stopped connection label describes its last observation, not a current connection query.

The display-age budget is `max(connection.stale_us, connection.poll_us) + 160000` microseconds. The additional 160 ms covers the sampler's 80 ms GUI publication cadence and the GUI's 80 ms repaint cadence. For the default 1 ms poll and 5 ms stale threshold, the display budget is 165 ms. This allowance avoids classifying ordinary GUI handoff delay as missing source updates. The displayed host age is still the full measured age; it is never reset or subtracted by this allowance. An observation exactly at the budget remains visible; an older one is hidden.

Source staleness is assessed independently at acquisition using the configured stale threshold and available freshness metadata. A GUI host-silence warning does not add stale/invalid rows or change CSV values, received counts, source-gap measurements, API/MQTT/shared-memory output or finalized timing. The shared cadence constant preserves the existing 80 ms sampler publication behavior. Held ages continue repainting on the Monitor tab after stopping without further transport access.

Snapshot adapters still expose host polls. Without source freshness metadata, source age/cadence/loss remain unknown. A recently received valid snapshot may be decoded, but it does not prove a new sensor update. Repeated equal or different values cannot supply that missing evidence. A late/out-of-order input still cannot replace the capture engine's displayed payload.

Final-run timing separately shows the recorded [host receive age at acquisition end](CAPTURE_REVIEW.md#terminal-host-receive-age). That fixed measurement stops before writer drain. The held GUI receive age continues advancing after stop; it is a different observation and is not copied into the finalized report.

## Offline and native test scope

`cargo test --locked --bin iolink-workbench desktop::observation` tests monotonic age advancement, unchanged receipt metadata/counters, GUI handoff allowance and exact boundaries, configured slow polling, invalid/unknown/stale quality, stopped/disconnected sessions, old observed updates, snapshot uncertainty and missing input.

The GUI self-test now includes six synthetic Monitor cases alongside the 24 profile/tab cases: recent input, held host input, stopped session, invalid input, old observed update and snapshot freshness unknown. A held completion channel models a running session without starting a worker or transport. Text-shape checks require retained raw bytes, the expected state label, and the presence/absence of the known typed value. The 30 views are painted twice, for 60 native offscreen passes and 122 hidden-window checks. No desktop input, screenshot, pixel readback or physical device is used.

These checks do not establish visible interaction, repaint scheduling under a real window manager, workstation DPI behavior or physical timing. During operator acceptance, use the simulator first: check live receipt ages, Stop and flush, retained raw input, and historical decoding. A blocked physical request remains subject to the selected gateway's timeout; test it only under the session's authorized read-only hardware scope.
