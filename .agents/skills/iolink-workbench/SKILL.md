# IOLinkWorkbench

Locate the user's checkout or extracted portable package. Read its `AGENTS.md` when working in source, then the relevant maintained document: `docs/OPERATIONS.md` for setup/CLI/mappings/capture review, `docs/DEVELOPMENT.md` for source flow/tests/releases, or `docs/INTERFACES.md` for planned consumers. The root README holds detailed options and the AL1350 protocol references. Prefer the executable's `--help` over guessing flags. This skill is useful with either binary-only packages or a Rust checkout.

For GUI navigation, read `docs/GUI_WORKFLOW.md`. Device, Inputs, Logging, Mappings, Parameters, Integration, Diagnostics and Offline separate the tasks. Connect… opens a read-only route review that checks the ifm origin and required confirmation of a conditional physical IODD layout. Logging uses the same checks. Connection review and Logging show enabled software feed destinations. Invalid enabled feed settings link to Integration and block Start. Use the repair links to reach Connection or Mappings. Connect… sits in the action bar, Profiles… separates bundled starters from Open & save, and Stop and flush stays above the tabs. Device opens a setup overview with task links and unresolved host/IODD notes; configured expectations remain separate from observed identity. Starting/loading a profile returns there without connecting. Starter replacement clears the old save path and is fenced by drafts, closing and setup owners. One dropped TOML profile or IODD XML/ZIP selects a path for explicit load/inspection; it never reads/applies files or connects. Open and Save use separate path fields; selecting an Open path does not redirect saving, while a successful load sets the save destination to the loaded file. Profile and IODD drops are fenced by the same setup owners/drafts, and a new IODD path clears stale inspection/ZIP selection while retaining import options for review. Secondary pages retain independent scrolling. Do not reconnect or start sampling merely to navigate. IO-Link stop ends acquisition and drains CSV; it does not preserve a separate EthernetIP-style connection owner.

## Choose the workflow

- Inspect bytes offline in Inputs opens a fixed copy of the displayed observation. From Inputs uses the mapping and receipt quality at copy time. Pasted bytes keeps its own draft, and cyclic acquisition continues.

- Search named parameters by name, IODD ID or decimal/hex index in Parameters → IODD reads and Offline → Parameter bytes. Select a match explicitly. IODD details and display preference contains defaults, mappings and value definitions. Expand Read and save a snapshot to save a new JSON file. Each acyclic action keeps its own last result with the original query. Device events shows the diagnostic result above the expandable IODD event catalog. Use Read and save a snapshot or CLI `read-diagnostics PROFILE --snapshot FILE` to preserve both queries and their connection context. Offline → Diagnostic snapshots and `review-diagnostics FILE` reopen this evidence using the embedded event catalog. Partial replies and observed master or device changes remain visible. Use Compare two snapshots or `compare-diagnostics LEFT RIGHT` for wire equality and conditional status/slot differences. Both saved reviews remain available with any context restrictions. Source event loss stays unknown.

- For device descriptions, inspect XML/ZIP with `iolink-cli iodd`, choose an exact variant/layout, then `import` to a new profile. Resolve local standard/language/unit resources explicitly. Preserve review notes and imported definitions; import does not verify connected identity. Vendor files and raw captures belong in ignored `.local/` in source checkouts. Re-import an IODD to enable padded standalone integer input geometry. `decode` and GUI inputs flag noncanonical padding while retaining exact bytes and typed low bits. Saved verification counts affected valid CSV rows when that geometry is recorded.
- For conditional layouts, `check-layout PROFILE` resolves the saved selector offline. `--read` or **Mappings → Layout condition → Read layout selector** checks one observation through the independent acyclic path. For whole-value access, distinguish the planned ISDU subindex 0 from the declared selector member. Compare the declared value with the unscaled result and review the observed port and read time before confirming the active condition.
- In diagnostic comparisons, pending-event counts group identical qualifier/code pairs across both saved 37:0 replies. Open **Wire slot positions** for the exact byte differences by slot. Comparable counts can match when slots moved. Other entries are reported separately, and the comparison leaves event history and loss unknown.
- Use **Offline → Event codes → ISDU ErrorType** or `decode-error-type HEX [--profile PROFILE]` for the two ErrorType bytes from a recorded negative ISDU reply. Import the IODD for localized vendor definitions and supply standard definitions to resolve references. Gateway status codes follow the gateway's own format.
- Use **Diagnostics → Connection & identity → Master and ports → Inspect master** or `inspect-master PROFILE` to read one configured ifm master and all its port metadata. Review missing fields and returned IoT Core codes without treating missing identity as a confirmed empty port. Use a separate per-device status check for acquisition pins.
- Standalone Boolean IODDs import an eight-bit input field. `00` decodes as false and any nonzero byte as true. Reimport older standalone Boolean layouts to apply the full-byte mapping. Packed Booleans stay one bit. Saved capture review counts noncanonical Boolean bytes among valid rows when the full-byte IODD layout is recorded.
- Fixed-length cyclic `OctetStringT` fields preserve wire order and zeros in GUI, CLI and CSV. Reimport to add these mappings or choose a manual byte-aligned field with `set-field --kind octet-string`. Saved raw captures can add octet columns through re-decode. Use the complete expected and desired hex images for reviewed output edits involving octets.
- Fixed-length cyclic `StringT` fields support UTF-8 and US-ASCII. Reimport the IODD or use the corresponding manual byte-aligned mapping. Typed and CSV views distinguish JSON-quoted text, malformed text, and blank cells. Encoding errors preserve raw bytes, source quality and neighboring fields. See the text columns section of `docs/CAPTURE_REVIEW.md`.
- Cyclic `TimeT` and `TimeSpanT` use byte-aligned, big-endian 64-bit mappings. The GUI and CLI show UTC or a signed duration along with exact ticks. Capture CSV and re-decode preserve exact ticks at 4,294,967,296 ticks per second. Keep device payload time separate from acquisition clocks and freshness.
- Reimport IODDs to show their `SingleValue` names on cyclic Boolean and integer fields. The named value uses the selected IODD language and exact unscaled data. CSV retains the ordinary field values. A change to the field's wire geometry or type through a manual override clears the names; restoring the IODD mapping recovers them.
- For manual setup, use `validate`, `set-connection`, `set-identity`, `set-field` and `remove-field`. These edit host profiles offline. Full input-payload `decode` previews bit offsets, width, signedness/type, byte order, scale and units. An imported name becomes an override; removal restores it. Never invent unknown scaling/units.
- For logging, use `set-logging` and offline `logging` to inspect mode, bounded queue, row/time rotation, selected mappings and exact CSV headers. Selection can be raw-only, all mapped or explicit ordered names. New profile destinations must not exist; unspecified settings remain intact. Reset dangling explicit CSV selections before removing a standalone field.
- In the GUI, use Verify latest recording in Logging or Offline to open and check the last finalized CSV folder from this app session. On Offline → Saved captures, drop capture.toml or receipt.toml to select its containing folder for explicit verification. Use Choose a signal to pick a logged field in verified CSV order. Raw captures without typed fields link to re-decode options. Use Exports to combine parts into one new CSV, re-decode or check a bundle. Compare captures takes two independent folders. New folder name keeps the destination parent. Check folder inspects the resolved parent and target on request, and Start repeats that check before launching the writer.
- In Logging → Multiple ports, review one saved TOML per port, set a new output folder and duration, and start the capture set. Try the two bundled simulator profiles first. Show port capture set returns from other tabs. Stop and flush drains all port writers, and Verify capture beside each result opens its individual saved bundle. A failure during close brings the capture-set results back into view.
- For acquisition, use an existing configured port and the current session's authorized endpoint. Check `status` and separate expected pins/IODD from observed identity. `capture` writes a new directory; `verify-capture`, `review-capture`, `redecode-capture` and `verify-export` operate on saved evidence. Keep originals unchanged.
- For saved interface diagnostics, use `review-interfaces DIRECTORY` or GUI Verify capture. Read `docs/CAPTURE_REVIEW.md`: all CSV parts are verified, raw-only captures work, exact saved interface counters/hashes are retained, and no live endpoint/mapping is opened. Missing metrics are not zero. Intentional coalescing, retention and uncertain delivery must not become source-loss totals. Offer counts are checked against acquisition only when the needed counters exist. Field review includes the same diagnostics when recorded.
- For offline comparisons, use `compare-captures LEFT RIGHT` or Offline → Saved captures → Compare captures. Compare as baseline stages the verified folder on the left. Use latest recording stages the latest finalized session recording on the right. Dropping capture.toml on Compare captures prompts for the baseline or right side. Assign or cancel the drop, then use Verify and compare to check both folders. Complete reviews and metadata hashes remain available. Read the comparison policy in `docs/CAPTURE_REVIEW.md`: no clock alignment or physical-origin inference, timing deltas require matching recorded context, counts and terminal receive-age deltas require equal acquisition windows where recorded, or equal origin-to-end elapsed time when both captures predate setup measurements, and missing/error context suppresses deltas. Keep each loss domain separate. Use `tools/verify_comparison.py` with explicit saved fixtures.
- Timed acquisition starts counting after local CSV and feed setup and includes connection attempts. The report elapsed time and row offsets still use the common session origin before setup. For timing failures, consult the recorded timing consistency section in `docs/CAPTURE_REVIEW.md`. All offline capture paths share quantile/frequency/count checks. Preserve originals; absent legacy statistics remain unavailable. Host intervals fit the acquisition window, but source clocks have independent bounds. Never derive full receive spacing from selected CSV rows or invent source cadence for snapshots. `tools/verify_timing.py CLI COUNTER_CAPTURE SNAPSHOT_CAPTURE` uses private copies and no live services.
- For terminal receive age, read `docs/CAPTURE_REVIEW.md#terminal-host-receive-age`. Final-run and saved review retain the optional host measurement at acquisition end, before writer drain. Exact last-row checks need complete received coverage and one-microsecond truncation tolerance. Filtered/dropped/legacy data do not establish the final receive; snapshot source age/loss stay unknown. Its comparison delta requires equal recorded duration. Use `tools/verify_terminal_age.py CLI COMPLETE FILTERED DROPPED SNAPSHOT` on explicit saved fixtures; no endpoint is opened.
- For saved identity, GUI review and `review-interfaces`/`review-capture` separate configured pins, last accepted master/device observations, rejected connections, producer check text and offline recheck. See `docs/CAPTURE_REVIEW.md`: known accepted-pin contradictions reject verification, while missing observations remain unavailable. Comparison includes observed master/device context; no live query, authentication or per-generation history is implied. `tools/verify_identity.py` tests private saved copies and endpoint independence.
- For capture accounting failures, read the selection/reconnect/source-gap section in `docs/CAPTURE_REVIEW.md`. Common offline checks cover available end-state, reconnect, poll/receive and eligible/selected/unchanged counts. CSV gap sums are checked only for complete every-update counter populations without logger drops, never across generations. Missing legacy populations stay unknown. `tools/verify_accounting.py` tests explicit complete, on-change, dropped-row and snapshot fixtures without live access.
- For saved quality failures, consult the validity/staleness/classification section in `docs/CAPTURE_REVIEW.md`. Common checks compare available category populations, captured stale threshold and explicit age/flag evidence. CSV category equality needs complete receive coverage; filtering/drops otherwise permit subset checks only. Invalid and stale counts overlap. Preserve unknown fields and source quality when re-decoding with a new mapping. `tools/verify_quality.py` uses private copied captures and parser-based CSV edits without live access.
- For GUI shutdown, read `docs/GUI_LIFECYCLE.md`. Normal close requests cyclic stop/flush and waits for pending reads, inspection, review and export, even on hidden tabs. New actions are disabled while closing; capture completion failures cancel exit and retain the error. Run `cargo test --locked --bin iolink-workbench desktop::shutdown` for modeled channel/viewport and simulator-flush checks. Actual visible/DPI/window-manager acceptance remains separate; desktop input/screenshots still require an explicit request.
- For GUI session startup, use `docs/GUI_LIFECYCLE.md#starting-a-session`. One cyclic owner remains until completion consumption. Pending drafts/inspection and closing block new starts; acyclic/review jobs stay independent. Fresh stop/display state is installed only after launch succeeds, preserving previous evidence on launch failure. `desktop::self_test::start_tests` uses denied dispatch, held channels and consecutive actual simulator captures without desktop input or hardware access.
- For live display age, read `docs/LIVE_VIEW.md`. Receipt quality and gateway age remain historical; host receive/update ages advance monotonically. The display-age budget includes the GUI handoff allowance. Held/stopped/disconnected or unusable input retains raw bytes and hides typed values without changing CSV quality or inventing snapshot freshness. Use `desktop::observation` tests and the six additional synthetic native-offscreen cases; visible scheduling and hardware acceptance remain separate.
- For CLI interruption, read `docs/CLI_LIFECYCLE.md`. Successful Ctrl+C/Windows Ctrl+Break drain returns 130 after report publication; writer/capture/integration failure returns 1 instead. In-flight requests finish under their timeout. `tools/verify_cli_shutdown.py CLI` uses its own hidden console, exact owned-PID checks and job containment for synthetic rotation/backpressure/timeout/failure cases. Never send console events to an existing user console. Native control-event results do not establish keyboard routing, console close, OS shutdown or physical acceptance.
- For parameters, `parameters`, `defaults` and `decode-parameter` are offline. Explicit `read-parameter --snapshot`, `read-diagnostics` and `isdu` use independent acyclic clients. `review-parameter` reopens embedded context offline. `compare-parameters LEFT RIGHT` and Offline → Parameter snapshot → Compare two snapshots compare exact bytes and preserve each read's context for a shared ISDU address. A declared default is not a device value or a write instruction.

## Non-obvious constraints

`status-ports PROFILE1 [PROFILE2 …]` reads distinct ports of one configured master in parallel, up to eight for AL1352 and four for AL1350 or simulator. It reports each independent status or failure and retains observations when a device pin differs. Use `capture-ports OUTPUT PROFILE1 [PROFILE2 …] --seconds N` for independent cyclic sessions with per-port queues, clocks and CSV bundles. Each output `port-N` folder works with existing offline review commands. `capture-set.toml` records each outcome after worker completion. Ctrl+C or Ctrl+Break requests a drain for the set.

In **Logging → Multiple ports**, review the saved profiles and choose **Read port status** for the same observations. This works for acyclic-only and output-only profiles and needs no capture folder. Expand a port's master, identity and diagnostics to inspect the details.

No master/sensor/signal has been selected in the initial project. ifm AL1350 IoT Core 3.1.x is a documented adapter target, not physical acceptance. Confirm selected hardware's firmware/interface/Windows support and license before adding an SDK or claiming compatibility.

Keep transport, pure decoding, cyclic capture, independent acyclic reads and CSV writer responsibilities separate. Source-update mode retains equal consecutive values only when freshness metadata verifies a new update. AL1350 and AL1352 snapshot rows are host polls; source-update loss, source age and gateway update cadence remain unknown. Do not infer freshness from value changes. On-change compares complete raw input plus quality/diagnostic changes, independent of typed-column selection.

Compare declared sensor minimum, reported port cycle, requested host polling, source/gateway cadence and host receive spacing separately. Treat 1 ms as an evaluation target. Report p50/p95/p99/longest gaps, stale/invalid/unknown data, reconnect boundaries, measurable source gaps and logger overruns. Preserve monotonic receive times, UTC start, indexes and bounded queue accounting. Distinguish intentional filtering from loss.

Physical writes require explicit user approval for the proposed target and operation. Use Read current value in Device → Writes or `iolink-cli read-current` for a checked read of a numeric mode, readable ISDU write target or full process output image. Device → Writes and `iolink-cli write` preview offline. For supported Boolean, integer, Float32, text, and octet string ISDU targets, enter the desired value with IODD value or `--desired-value` and keep the exact expected hex. Inspect the proposed ISDU value interpretation and any manual review note from the profile IODD. Whole record and array previews require complete expected and proposed images and reject changes outside declared writable members. Apply reviewed write or CLI `--confirm` dispatches the approved AL1350 operation after live checks. The GUI waits for the write during close and retains an unconfirmed result. Keep cyclic and feed paths read-only. See `docs/WRITES.md` and test writes with `tools/verify_writes.py` on loopback. Use session authorization for physical reads. Desktop input and screenshots or recording need an explicit request in the current chat. The hidden native self-test uses only its own process and an offscreen framebuffer.

In Device → Writes, Choose from IODD lists eligible parameter addresses and subindexes. Use selected address fills the numeric draft fields offline. Changing the address clears the old expected and desired values.

For CLI `read-current … isdu` and `write … isdu`, use either `--index` or `--parameter-id` with the exact imported IODD ID. The ID resolves locally. The preview and confirmation use the resolved address and exact bytes.

Checked ISDU current-value reads show Observed IODD details in the GUI and an optional `iodd_value` in CLI JSON. Use the original observed `value` as exact expected hex. The interpretation retains decode errors and domain findings alongside those bytes.

For a matched IODD parameter, the offline preview compares the supplied expected bytes with the proposed bytes and lists changed record or array members. CLI JSON stores this in `isdu_comparison`. Preflight still reads the current bytes independently before dispatch.

For a one-member whole-image edit, keep the write at subindex 0 and supply the complete expected bytes. Use Edit one member or CLI `--member-subindex` with `--desired-value`. Inspect the resulting complete wire image and changed member before approval.

For a paired IODD output layout, an offline Process output preview compares typed expected and proposed values and flags changed bits without a mapping. Use the complete gateway output images at the declared width and preserve padding. Confirm a conditional layout against the device before preview. Import an output-only layout by ID in the GUI or with `import --layout ID`. The profile supports status, parameters, output inspection and reviewed writes. Input acquisition and CSV require an input layout. Select an acyclic-only IODD layout for status, ISDU, snapshots and diagnostics without cyclic data. Use Edit one field or `--field NAME --desired-value VALUE` to replace one mapped value while preserving the rest of the expected image. Values are unscaled. For standalone Boolean output, writes use 00 and FF and readback compares exact bytes. Padded standalone integer outputs use sign or zero padding and show warnings for noncanonical observations. Re-import earlier IODDs to enable these standalone encodings. Re-import v0.79.0 profiles to enable editing packed fields. Checked output reads show IODD output fields when the width and recorded condition permit decoding. `decode-output PROFILE HEX` and Offline → Process bytes → Output bytes inspect saved images using the selected layout.

For a single supported `StringT` value, the preview includes the IODD encoding and length for readback. Preflight compares exact bytes. After acknowledgement, `text_readback_matched` identifies equal decoded text with different zero padding and retains the exact returned bytes.

Typed integer ISDU drafts support 2- to 64-bit values in 1-, 2-, 4- or 8-byte containers. A standalone typed Boolean true encodes as `FF`. Generate a new preview for typed true operations reviewed before v0.73.0. Existing compact representations still decode.

Typed `TimeT` drafts take an explicit UTC timestamp ending in `Z`. Typed `TimeSpanT` drafts take `[+-]PTseconds[.fff]S`. Review the exact eight bytes and ticks because fractional values at millisecond precision may round to the next tick in magnitude. Temporal preflight and readback compare exact bytes.

## Changes and delivery

For research/cleanup, start with `docs/RESEARCH.md` and the artifact retention section of `docs/DEVELOPMENT.md`. Preserve original vendor inputs, read-only references and current/previous releases. Verify active ownership, resolved boundaries and archive hashes before removing loose evidence or rebuildable output. Use maintained verifiers with explicit fixtures instead of new copied private release scripts. Cleanup receipts and raw/source material remain ignored; cleanup alone does not require a new application build.

Use `docs/DEVELOPMENT.md` for actual commands: Cargo formatting/tests/Clippy, CLI-only build, `tools/verify_headless.py`, capability-checked `tools/verify_gui.py` and `tools/package_windows.py`. Keep simulator, HTTP loopback, hidden native GUI and physical results distinct. Do not launch old GUI binaries to probe arguments. Test extracted portable binaries and prior CLI compatibility when changing stored schemas.

The opt-in local HTTP API runs only during acquisition: GUI Read-only local API or CLI capture `--api-listen 127.0.0.1:PORT` (0 chooses a port). Read `docs/LOCAL_API.md` for schema/status/history, numeric Host policy, session cursors, bounds and independent loss/age. It exports all normalized responses before CSV filtering, including duplicate/late classifications. Never equate API sequence, receive index and CSV sample index. Use `tools/verify_local_api.py` for synthetic/loopback checks. Runtime API options are not profile keys.

Optional MQTT publishing uses a separate latest-state worker: GUI checkbox or CLI capture `--mqtt-broker IP:PORT`. Read `docs/MQTT.md` for interval/topic/queue bounds, anonymous TCP QoS 0, no retained messages, coalescing, reconnect/shutdown and saved counters. Socket completion is not delivery confirmation. Use `tools/verify_mqtt.py` for the local protocol peer and synthetic input checks. Runtime MQTT options are not saved profile keys.

Optional Windows shared memory uses a separate queue and latest-snapshot worker: GUI checkbox or CLI capture `--shared-memory NAME`. Read `docs/SHARED_MEMORY.md` for Local object names, protected DACL, fixed little-endian header, named-mutex synchronization, raw/typed JSON, age/PID-creation checks, collisions and shutdown. `read-shared-memory NAME` needs no profile/hardware; the Python reference reader is in `examples/shared_memory_reader.py`. A reader holding the mutex causes publisher skips, not acquisition waits. Do not equate commit sequence/replacements with source loss or confirmed reader delivery. Check age/process state even when an old snapshot says active. Use `tools/verify_shared_memory.py` for native/synthetic checks. Runtime options are not saved profile keys.

Optional C FFI remains roadmap work. Consult the interface document before implementing; each consumer needs an independent bounded handoff, visible loss/age and no sampler blocking. Evaluate whether a C# host needs hardware-connection ownership before choosing FFI. Reference applications' capabilities are not capabilities of this app.

Update operator/developer docs and this skill with public behavior. Source samples must be synthetic/sanitized. Preserve unrelated work and read-only references; package from a clean verified commit. Publish commits only when the session authorizes it; this skill grants no external-write permission. Avoid automatic GitHub Actions spending.
