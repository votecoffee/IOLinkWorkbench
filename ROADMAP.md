# Roadmap

## Windows preview

- One-shot ifm master inspection reads master identity and metadata for every port from one saved profile. The GUI and CLI retain unavailable device fields and gateway codes, with model and firmware checks before reading ports.

- Read-only ifm AL1352 routing supports status, cyclic input capture and explicit ISDU reads on ports 1–8. Loopback verifies the high port addresses, model check and eight independent capture bundles.

- Decode recorded device application ErrorTypes in GUI and CLI. The offline lookup reads both code bytes and resolves localized vendor terms and standard references from the saved IODD catalog.

- Cyclic Boolean and integer fields show localized IODD state names in live, offline and reviewed output views. Names match exact raw values, including packed record members and array elements. Typed CSV cells retain their Boolean and engineering representation.

- GUI multi-port status reads use reviewed profiles and report master, identity and diagnostics for each port. Results stay visible when another port fails. Acyclic-only and output-only profiles support status checks before a CSV destination is selected.

- Conditional layout checks resolve the saved IODD selector offline and compare an explicit acyclic read with the declared value. Records and arrays with individual access disabled use a whole-value read and select the declared member from its reply. The operator can review matches, mismatches, and undecodable replies in Mappings or CLI. Loopback checks hold a selector read while cyclic polling continues.

- Cyclic `TimeT` and `TimeSpanT` support scalar, record, array and manual mappings. GUI and CLI show timezone-independent UTC or signed durations. CSV and offline re-decode preserve exact ticks, separate from capture timing.

- Cyclic UTF-8 and US-ASCII `StringT` values retain raw bytes and isolate encoding errors to their field. GUI, CLI, CSV, Signal review and offline re-decode distinguish valid empty text, malformed text and unavailable cells.

- Cyclic `OctetStringT` scalar, record, and array values preserve ordered bytes in the GUI and CLI. Input CSV, saved verification, and raw-capture re-decode support the same mapping. Manual fields accept byte-aligned widths up to 32 bytes.

- Imported standalone integer inputs derive standard padded wire widths. Live and offline views flag noncanonical padding, and saved verification counts affected valid CSV rows.

- Standalone Boolean inputs decode the whole byte. Live and offline views flag noncanonical true bytes, and saved verification counts affected valid CSV rows. Older and packed one-bit mappings preserve their saved interpretation.

- Compare saved diagnostic snapshots in GUI and CLI. Matching recorded context and valid replies enable Device Status comparison, counts of pending qualifier/code pairs, and a separate view of wire-slot positions.

- Save explicit Device Status and Detailed Device Status reads as a JSON snapshot with per-query bytes, errors and connection context. GUI and CLI review use the embedded IODD event catalog and retain partial results and changed-master/device observations.

- Logging → Multiple ports reviews saved profiles, runs independent port captures, and shows live port observations and individual saved results. The header controls stop and flush across pages.

- CLI capture can run independent cyclic sessions for up to four explicitly configured ports on one master. Per-port CSV, reconnect and timing reports are published alongside a batch outcome. Simulator, AL1350 loopback and isolated Windows interruption tests cover independent drains and partial failures.

- Standalone IODD integer output editing regenerates sign or zero padding in the applicable wire container. Checked and offline reads retain mismatched padding and flag it for review.

- Saved parameter snapshots compare exact bytes and retain independent decoded values, identity and diagnostics. Matching composite definitions and observed device types permit per-member comparisons.

- CLI status reports read up to four explicitly profiled ports of one master concurrently, retaining each result and identity check when another port fails. Verified on simulator and AL1350 loopback.

- Standalone IODD Boolean outputs use 00 and FF for reviewed writes. Checked reads and offline decoding retain noncanonical bytes with an interpretation warning. Preflight and readback compare the exact image.

- An explicit empty IODD process data layout can be imported for status, ISDU, parameter snapshots and diagnostics. Acyclic-only profiles block cyclic input and output paths and keep the applicable device workflows available.

- Import an output-only IODD layout into a profile for offline output inspection, status, ISDU reads and reviewed outputs. Workbench rejects input monitoring and capture before opening a cyclic session. Manual input mappings are retained for later review.

- Checked process-output reads retain the raw gateway image and show the paired IODD field values when the image width and recorded layout confirmation permit interpretation. The GUI and CLI can also decode pasted output images offline under the selected layout.

- Process output drafts can replace one IODD field in the exact expected image. The GUI and CLI show the entire proposed image for the same width, padding, approval and preflight checks as a raw draft. Supported values include packed Boolean, signed and unsigned integers, and finite Float32.

- The selected IODD input layout retains its paired process output declaration. Offline full-image output previews show typed expected and proposed values and changes to unmapped bits. The preview checks byte width, padding and recorded layout confirmation. IODD inspection lists output-only layouts separately.

- A typed member edit can build a complete record or array write at subindex 0, including for IODDs with direct subindex access disabled. The proposed image keeps every bit outside the selected member.

- ISDU previews show expected and proposed IODD values together, with before-and-after member bytes for whole records and arrays. The comparison appears in CLI preview and receipt JSON.

- The CLI accepts an exact imported IODD parameter ID for checked ISDU reads and reviewed writes. The resolved index and subindex are the addresses used for review and approval.

- Checked ISDU current-value reads show the matching IODD interpretation, including engineering displays and decoding issues. The exact returned hex remains available for the expected-value check.

- Device → Writes can search imported IODD names, IDs and indexes for eligible ISDU parameters and subindexes. An explicit selection fills the numeric address, and changing the address clears the draft values.

- Reviewed single `StringT` writes distinguish exact readback from the same IODD text returned with different zero padding. Expected bytes still require an exact match before dispatch. Receipts retain the returned bytes.

- The GUI and CLI encode typed Boolean, 2- to 64-bit integer, Float32, time, duration, text and octet string ISDU drafts from the imported IODD. Integer drafts use standard wire containers, and a standalone Boolean true encodes as `FF`. Temporal entry uses millisecond precision and shows exact fixed-point ticks at review.

- ISDU write previews show the IODD interpretation of proposed bytes, including whole records and packed arrays. They reject supported datatype and value-domain failures offline and require bits outside declared writable members to match the expected image. Unsupported or ambiguous value definitions remain flagged for manual review. Bench qualification remains open.

## First physical bench

1. Record the master model, hardware and firmware revision, IoT endpoint, actual configured port mode, sensor model, and IODD revision. Record the intended signal and unit.
2. Verify the device IDs and selected variant, active process-data layout, width, validity behavior, and a known value against the vendor's viewer or another independent read. Record the negotiated IO-Link cycle and the source that confirms its unit.
3. Capture a timed trace at the requested 1 ms host interval and at a sustainable interval. Compare host poll and receive distributions, invalid data, terminal silence, retries, and writer overruns. For AL1350 snapshots, report the gateway update rate and source loss as unknown. For an adapter with per-update metadata, compare source counters and timestamps independently of the host.
4. Record a separate capture with an explicit ISDU read on its own worker and measure any gateway-side effect on host timing. Keep real bench results separate from simulator and loopback results.
