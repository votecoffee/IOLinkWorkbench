# Roadmap

## Windows preview

- Shared one-port capture engine, portable GUI and CLI, saved profiles, manual mapping, and offline IODD inspection and decoding.
- Headless checks for equal consecutive updates, change-only recording, snapshot labeling, invalid and stale inputs, reconnects, queue backpressure, and CSV rotation.
- Saved logger telemetry measures observed queue high water, dequeued rows, queue wait, row service, CSV flush/file-sync attempts, and final stop/drain. GUI and CLI signal review retain the recorded measurements separately from source and receive cadence. Tests cover empty writers, backpressure, rotation failures, corrupt timing/count claims, and older reports without metrics. Measurements include p50/p95/p99/longest/mean; physical disk and 1 ms qualification remain separate.
- Capture reliability checks cover frozen counters with zero reported age, retrying dropped changes, and reporting unconfirmed rows after a CSV rotation failure.
- GUI CSV selection supports mapped-value checkboxes, IODD/manual/override labels, explicit column ordering, all-values reset, and raw-only logging with retained mappings. CLI capture accepts ordered repeated field overrides, raw-only, and all-fields options. Saved profiles persist the effective choice. Tests cover atomic selection failures, legacy defaults, mapping preservation, raw-only rotation/verification/re-decoding, Unicode field names, and snapshot freshness labels.
- IODD checks cover display scaling, explicit no-unit metadata, ambiguous variant and datatype IDs, and overlapping supported input fields.
- Offline capture verification checks rotated CSV parts against the saved profile and report, with optional combined CSV output. Rejected reconnects retain the accepted capture identity and record the rejected candidate separately.
- Offline signal review verifies every field and CSV part while streaming one logged field into bounded time bins. The GUI adds independent min/max range marks, last-value points, gap/reconnect review cues, and recorded acquisition timing. CLI review exposes finite/blank/non-finite counts, approximate numeric statistics, exact first/last nonblank cells, and saved transport/simulation context. Synthetic and loopback checks cover rotated and change-only runs, invalid/stale values, reconnects, logger overruns, wide integers, non-finite values, empty captures, and corruption in unselected fields.
- Offline re-decode exports verify the original run while applying another saved mapping to raw payloads. New CSV bundles preserve metadata cells, source profiles/reports, acquisition error/loss meaning, and stream-derived SHA256 receipts. GUI export uses the applied Setup profile. Synthetic and loopback checks cover changed mappings and field order, byte order, Unicode CSV headers, invalid/stale rows, reconnects, overruns, wide integers, source corruption, input-width errors, failed final flush, and destination collisions.
- Re-decoded bundle verification checks fixed local files, hashes, derived CSV values, metadata order, mapping claims, and row accounting. Optional explicit original-source verification rechecks every source field/part and compares source hashes and copied cells in the same stream. GUI and CLI distinguish local consistency from source comparison and preserve acquisition errors. Tests cover portable/relocated bundles, rehashed semantic corruption, edited payloads, byte changes, malformed inventories, bounded metadata, wide values, and empty captures.
- Explicit IODD variable catalogs persist names, indexes, access rights, defaults, choices, and ranges. Named scalar and text parameter reads use the acyclic client, with raw payloads retained on decoding errors.
- Optional local IODD standard definitions resolve referenced parameters into saved profiles. Numeric menu displays retain separate scaling, units, formatting, and raw values. Standard references are resolved from the supplied local definitions; menu formats and mappings are retained in saved profiles.
- Acyclic displays support integer Bin/Hex, plain Dec, decimal precision, and Boolean Dec (0/1), with raw values retained. Signed radix values extend to 8/16/32/64 bits and preserve exact 64-bit values. Scalar, record, array, and member reads share the offline formatter. Invalid datatype/scaling/unit combinations remain visible for review. Synthetic and loopback tests exercise the new formats; all 22 official examples still import, retaining 63 supported decimal parameter displays in the current offline audit.
- Saved parameter display preferences can be selected and cleared in the GUI and offline CLI. Scalar and record-member choices retain raw values and every available view; array choices apply to every element. Candidate validation rejects stale IDs and preserves the original profile on failure. Synthetic and loopback checks cover persistence, whole/member reads, clearing, malformed responses, and rejection before transport access.
- Explicit named parameter reads can save an atomic, non-overwriting JSON snapshot with raw bytes, query, profile, observed master/port/identity, and host timing. GUI and CLI reopen it offline using the embedded mapping. Tests cover whole/member scalar/record/array responses, display preferences, exact 64-bit values, Unicode, malformed responses, bounded/strict JSON, corrupt context, no-network reopening, destination preservation, and continued cyclic sampling during a held snapshot read. Local consistency remains separate from acquisition-origin and physical bench acceptance.
- Parameter records preserve member layouts, defaults, access restrictions, standard record references, and menu display metadata. Whole-record and named subindex reads share the offline ISDU decoder. An offline import of the 22 official XML examples retained 46 records and 406 members. Synthetic and loopback checks cover member reads, whole-record decoding, malformed members, read restrictions, and 232-byte payloads.
- Top-level cyclic arrays expand into named typed/CSV fields. Acyclic arrays preserve element metadata and support whole-array and permitted subindex reads, with per-element display scaling and standard count restrictions. The 22 official examples imported with 24 array definitions and 139 elements after standard restrictions. Synthetic and loopback checks cover packed ordering, octet boundaries, raw sign padding, array CSV fields, malformed responses, and read restrictions.
- Optional local XSD 1.0 validation checks the selected main XML against a supplied schema closure using Windows System.Xml. Imports can require a pass and persist XML/schema hashes. GUI inspection uses a background worker. All 22 official example IODDs passed against the supplied 2025 schema set. Tests cover failed-import preservation, local includes, blocked external resolution, DTDs, schema hints, receipts, and helper timeouts.
- Standard-definition localization follows the selected device language with embedded/adjacent translations and an explicit local override. Saved provenance and fallback IDs distinguish primary from translated labels. Tests cover scalar/record choices, events, profile/snapshot persistence, CLI argument requirements, missing resources, conflicts, unknown/duplicate IDs, and revision mismatches. Offline audits accepted eight supplied standard translations, 22 main examples, and four German/Chinese example selections; the supplied Korean file is rejected for a release-date mismatch. Vendor resources remain outside the repo/package.
- Selected-language imports support embedded text and bounded XML/ZIP companions, primary-text fallbacks, and Direct Parameter Page 2 text redefinitions. Optional unit definitions extend the built-in abbreviations and persist their source/version. The full 688-entry official unit table imported with all 22 examples; German and Chinese imports passed for both official internal/external language examples. Synthetic checks cover Unicode CSV fields, ambiguous companions, mismatches, fallbacks, and new unit codes.
- IODD event catalogs retain localized names and descriptions, types, and supplied standard references. Explicit Device Status and Detailed Device Status reads use independent acyclic clients and retain partial successes, per-query timing, raw payloads, and observed identity changes. The GUI and CLI share the offline qualifier/code decoder. An offline audit of the 22 official examples retained 136 event definitions, resolving 90 standard references with none unresolved. Synthetic and loopback checks cover malformed slots, empty entries, source namespaces, identity changes, partial failures, and continued cyclic polling while a diagnostic read is held.
- Documented ifm AL1350 IoT Core adapter with an isolated JSON loopback fixture. Physical acceptance begins once the master and sensor are selected.

## First physical bench

1. Record the master model, hardware and firmware revision, IoT endpoint, actual configured port mode, sensor model, and IODD revision. Record the intended signal and unit.
2. Verify the device IDs and selected variant, active process-data layout, width, validity behavior, and a known value against the vendor's viewer or another independent read. Record the negotiated IO-Link cycle and the source that confirms its unit.
3. Capture a timed trace at the requested 1 ms host interval and at a sustainable interval. Compare host poll and receive distributions, invalid data, terminal silence, retries, and writer overruns. For AL1350 snapshots, report the gateway update rate and source loss as unknown. For an adapter with per-update metadata, compare source counters and timestamps independently of the host.
4. Record a separate capture with an explicit ISDU read on its own worker and measure any gateway-side effect on host timing. Keep real bench results separate from simulator and loopback results.

## Follow-on work

- Add one documented source-counter or timestamp transport once selected hardware exposes it. Qualify timestamp clock, counter wrap, update semantics and firmware-specific behavior.
- Add multiple independent port sessions with per-port identity, status, and capture accounting.
- Expand IODD handling for profile snippets and IODD Checker semantic/stamp rules. Add representative sanitized fixtures for supported device families.
- Add event-history acquisition only when a selected transport documents event delivery, ordering, and loss semantics. Current explicit diagnostics are snapshots with unknown source event loss.
- Expand parameter decoding for nested layouts and remaining datatype-specific displays.
- Consider any configuration or output features only after explicit authorization for the specific operation and bench setup.
