# Roadmap

## Windows preview

- Optional MQTT 3.1.1 TCP QoS 0 latest-state publishing in GUI/CLI with no retained data or subscriptions. Its preallocated queue and dedicated worker keep broker backpressure separate from sampling, API history and CSV. Payloads preserve raw/typed quality, source generations/clocks, configured mappings, host age and distinct sequence/loss meanings. Final reports verify handoff/coalescing/publish accounting. Tests cover framing, fragmented/refused handshakes, keepalive, reset/stalled/non-reading peers, stale/invalid data, snapshots, independent API/CSV operation and shutdown. This uses an original loopback peer; production-broker, physical timing and visible GUI acceptance remain pending.

- Opt-in read-only loopback HTTP API in GUI/CLI with independent preallocated handoff and bounded history. Schema/status/history preserve raw/typed inputs, response classifications, identity generations, session clocks/cursors and separate API/CSV/source accounting. Request/response size and time limits isolate slow clients; finalized reports retain verified queue/history counts. Rust and synthetic loopback checks cover queue saturation, size pagination, stale/invalid/duplicate/equal values, reconnects, on-change filtering, CSV backpressure, malformed requests and shutdown. Physical timing and visible GUI interaction remain pending.

- Saved logging edits and offline capture plans share validated candidates across GUI/CLI. Plans expose configured freshness meaning, ordered typed mappings/origins and exact CSV headers without transport access. Headless checks cover scalar/selection preservation, row/time rotation, source/destination preservation, unreachable endpoints and clearing selections before manual-field removal. Operator/developer guides, repository instructions and a discoverable Codex skill accompany the portable package.

- GUI cyclic-field editing and offline CLI set-field/remove-field share complete-profile validation. Controls expose bit layout, type, byte order, engineering conversion and decimal precision, with a full-payload offline preview. Imported fields remain intact beneath overrides; removal restores them and rejects dangling CSV selections. New profiles preserve source bytes and all other settings. Tests cover bounds/invalid types, exact wide values, endian/sign/scaling, order/selection preservation, snapshots and CSV capture. Native offscreen Setup cases include the active field editor. No transport or device configuration path is added.
- A standalone GUI self-test creates a hidden native Windows OpenGL context and paints 24 built-in profile/tab views offscreen in 48 passes. Native visibility, framebuffer, geometry, GL errors, applied-profile preservation and background-worker denial have explicit checks and a new non-overwriting JSON receipt. The developer verifier refuses older binaries without the capability marker. Cargo tests cover view construction and safety guards without native windows. No input injection, screenshots, pixel readback or gateway access is used. Visible-window interaction, DPI behavior and physical bench acceptance remain pending.

Pending drafts share the acquisition guard; IODD Product ID conflicts remain visible without changing the mapping. New profiles preserve all other settings and source bytes, with no overwrite or gateway access. - GUI host connection settings and offline CLI set-connection share candidate validation and the transport's origin check. New CLI profile publication refuses overwrites and preserves source bytes, mappings, identity pins, preferences, IODD metadata and logging settings. Tests cover invalid/partial edits, interval bounds, incomplete templates, inactive settings, destination preservation, legacy storage, snapshots and continued simulator/HTTP loopback acquisition. These controls edit host profiles only; physical configuration and visible GUI interaction acceptance remain separate.

## First physical bench

1. Record the master model, hardware and firmware revision, IoT endpoint, actual configured port mode, sensor model, and IODD revision. Record the intended signal and unit.
2. Verify the device IDs and selected variant, active process-data layout, width, validity behavior, and a known value against the vendor's viewer or another independent read. Record the negotiated IO-Link cycle and the source that confirms its unit.
3. Capture a timed trace at the requested 1 ms host interval and at a sustainable interval. Compare host poll and receive distributions, invalid data, terminal silence, retries, and writer overruns. For AL1350 snapshots, report the gateway update rate and source loss as unknown. For an adapter with per-update metadata, compare source counters and timestamps independently of the host.
4. Record a separate capture with an explicit ISDU read on its own worker and measure any gateway-side effect on host timing. Keep real bench results separate from simulator and loopback results.

## Follow-on work

- Qualify MQTT against selected production brokers and add TLS/authentication only with explicit endpoint/credential handling, bounded reconnect behavior and tests. QoS 1/2, durable replay and subscriber receipt confirmation are outside the current latest-state contract.

- Add a versioned Windows shared-memory latest raw snapshot with coherent status/identity/timing, sequence and reader-consistency/lifecycle contracts. Account for overwritten observations independently of source and logger loss.
- Evaluate optional C-compatible FFI for C# embedding, including whether the C# host must own the hardware connection. Define ABI lifetime/thread/error/cancellation/panic boundaries before implementation. FFI is discussed future work, not implemented here or in the EthernetIPWorkbench reference when this item was added.
- Maintain operational/developer documentation, AGENTS.md and the Codex skill as public workflows evolve. See [interface design and acceptance criteria](docs/INTERFACES.md); shared memory and C FFI remain future work.

- Add one documented source-counter or timestamp transport once selected hardware exposes it. Qualify timestamp clock, counter wrap, update semantics and firmware-specific behavior.
- Add multiple independent port sessions with per-port identity, status, and capture accounting.
- Expand IODD handling for profile snippets and remaining IODD Checker semantic rules. Checksum consistency is implemented; official Checker execution and vendor authenticity remain separate. Add representative sanitized fixtures for supported device families.
- Add event-history acquisition only when a selected transport documents event delivery, ordering, and loss semantics. Current explicit diagnostics are snapshots with unknown source event loss.
- Expand remaining datatype-specific displays and profile-specific decoding. IODD RecordT/ArrayT elements are simple datatypes; unsupported complex elements stay on the raw/manual path.
- Consider any configuration or output features only after explicit authorization for the specific operation and bench setup.
